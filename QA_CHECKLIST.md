# Контроль качества отчётного лендинга ЦЛП

Это обязательный чек-лист перед отправкой пользователю ссылки на обновлённый отчёт. Проверка синтаксиса JavaScript сама по себе **недостаточна**.

## 1. Проверка исходных данных
- Сверить значения за новый месяц с сообщением пользователя / утверждённой выгрузкой.
- Проверить сложение по категориям и отсутствие двойного учёта людей.
- Проверить исторические числа, правильность сравниваемого месяца и проценты.
- Не выдавать расчётное значение за подтверждённую выгрузку.

## 2. Функциональное тестирование (smoke test)
- Открыть сайт по публичному адресу, а не только файл в репозитории.
- Убедиться, что видны все три KPI (не пустые и не равны нулю).
- Проверить наличие трёх составных полос в сравнении годов.
- Проверить, что линейный график содержит точки и линии за три учебных года.
- Переключить «Сентябрь» и «Октябрь» и проверить числа, выводы, диаграммы.
- Переключить три показателя линейного графика.
- Навести курсор на график и проверить карточку точных значений.
- Раскрыть «Сводную таблицу» и проверить десять месяцев и текущую строку.
- Поочерёдно скрыть и восстановить каждую группу столбцов, в том числе Δ%.
- Проверить отсутствие ошибок JavaScript в консоли браузера.
- Убедиться, что анимация не может скрыть данные при сбое IntersectionObserver / выключенном JavaScript.

## 3. Проверка мобильной версии
- Ширина экрана 390 px и 360 px: карточки, подписи и кнопки не накладываются друг на друга.
- График виден полностью, не обрезает важные подписи.
- Таблица прокручивается внутри своего блока по горизонтали, без горизонтальной прокрутки всей страницы.
- При касании графика появляется подсказка, её можно закрыть.
- Кнопки достаточно крупные для нажатия пальцем.

## 4. Регрессионное тестирование
После **любой** правки текста, CSS или JS повторно выполнить пункты разделов 2 и 3. Особенно проверять, что не перестали отображаться диаграммы. Не изменять функциональные участки кода при чисто редакторских правках без необходимости.

## 5. Подтверждение релиза
- Проверить, что GitHub сохранил коммит.
- Проверить фактическую опубликованную страницу GitHub Pages.
- Зафиксировать, какие проверки успешно выполнены, а какие нет.
- **Не сообщать «всё проверено»**, если проверено только наличие кода или синтаксис. В таком случае честно указать, что браузерное QA не выполнено.
